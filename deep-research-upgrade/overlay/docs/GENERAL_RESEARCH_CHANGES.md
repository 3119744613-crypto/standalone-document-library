## 这次增加了什么

| 部分 | 当前实现 | 与已有代码的关系 |
|---|---|---|
| 通用工作台 | 同一个页面提供“通用研究”和“资料管理”，支持本地账号与任务切换 | 新增 `apps/web/general.html`、`src/general-main.jsx` 和 `src/features/general-research/`；复用原前端基础设施 |
| 资料生命周期 | 创建资料库、上传、解析、索引、预览、关键词检索、删除及失败重试 | 将原生资料库 0.2 的 MD/TXT 能力扩充到文本 PDF、DOCX；不使用 Yuxi 服务 |
| 研究计划 | 先生成可编辑的需求理解、研究步骤与公开检索词；等待用户确认才执行 | 新增通用研究状态机，创建草稿本身不调用模型 |
| 多 Agent 执行 | 规划、资料研究、公开资料研究、来源核验、报告撰写各自记录状态与输出；两类研究可并行 | 不同角色对应独立模型请求；不是仅给界面卡片取不同名字。真实服务联调仍须单独验收 |
| 联网资料 | 用用户审核后的公开检索词搜索，再读取可访问网页的正文 | 当前实现为 Brave Search 适配器；网页读取失败时不把搜索摘要伪装为已读取正文 |
| 报告与引用 | Markdown 报告、来源卡片、本地文档定位、公开网址、报告下载 | 校验引用 ID 存在，要求报告同时引用所选文档和公开来源；不把这种校验等同于事实完全正确 |
| 进度与恢复 | SSE 进度事件、事件游标回放、取消、重启中断状态、迟到响应隔离 | 复用已有通用 SSE 读取器；当前模型接口为非流式文本响应，页面流式显示的是执行进度，不是逐 token 输出 |
| 资料删除联动 | 删除被引用资料后，关联通用任务失效，并清除其片段、计划、角色输出与报告 | 清理发生在本通用模块的数据空间；不会触及原业务任务或数据库 |
| 配置与交付 | 独立模型、搜索与解析器配置，个人本机运行 | 使用自己的 API Key；资料管理可以离线使用，完整联网研究需要可用模型和搜索服务 |

“来源核验 Agent”是另一轮模型检查，负责检查来源与研究结论的对应关系。它不能替代人工查证，也没有执行文档解析产品的性能基准测试。报告不得把未运行的性能或质量对比写成实测结论。

## 四种文档格式的真实范围

| 格式 | 提取与引用方式 | 限制 |
|---|---|---|
| 文本型 PDF | 按页提取文本，保存 PDF 页码及提取文本行范围 | 最多 200 页；不执行 OCR；纯图像或无文本文件明确失败，加密文件不支持；混合文件的无文本页显示警告 |
| DOCX | 正文段落与表格单元，保存段落或表格/行/单元位置 | 不提供页码；不提取页眉、页脚、批注、图片；修订、文本框或嵌套表格可能不完整，并显示提示 |
| Markdown | 严格 UTF-8 文本及行号 | 当作资料原文处理，不执行内嵌 HTML 或脚本 |
| TXT | 严格 UTF-8 文本及行号 | 非 UTF-8 或含二进制控制内容时明确失败 |

单文件上传上限为 10 MiB，提取文本上限为 2 MiB。PDF/DOCX 需要 Python 3.11+ 及固定版本解析依赖，采用独立子进程、20 秒超时、输出限额和单任务并发；MD/TXT 无需 Python。DOCX 还检查压缩包展开体积、压缩比、重复成员、路径、宏与 XML 实体。

一次研究选择同一资料库内 1 至 6 份已索引文档。系统按预算读取每份文件的有限片段，并保留每份所选文件的依据；没有承诺每次都逐字阅读全部文档。检索为关键词匹配，首版没有向量语义检索。

## 数据与功能隔离

新增通用服务只监听本机。它使用本模块自己的本地账户、`.env.general` 配置和数据目录；默认包含 `library.sqlite` 与 `research.sqlite`。原领域 Agent、工具注册、业务数据库和原有运行配置没有被接入这条通用研究链路。

只有用户允许后，任务描述和必要资料片段才会发送给其配置的模型服务；公开搜索使用经用户审核的检索词。网页、资料内容和其他 Agent 输出按不可信材料处理，不能借此取得 shell、账户凭据或原业务工具权限。本地保存不意味着模型调用也在本地执行。

本轮不增强原项目中的军事研究、武器研发、装备能力生成或作战推演流程，也不向这些流程提供资料检索。原业务功能留在自己的入口与数据空间中，不属于本次通用研究验收。

## 与前两个资料库版本的区别

| 版本 | 实际用途 | 运行依赖 |
|---|---|---|
| 旧 Yuxi 适配器 | 将资料操作转发到 Yuxi | 需要独立运行的 Yuxi 后端；保留作历史记录，不是本轮推荐入口 |
| 独立资料库 0.2 | 单机 MD/TXT 资料管理和关键词检索 | Node.js 与本地 SQLite；没有完整研究流程 |
| 当前通用模块 0.3 | 在原仓库内提供资料管理、计划确认、多 Agent 研究、来源与报告 | Node.js；PDF/DOCX 另需 Python 解析依赖；完整研究另需模型及搜索服务配置 |

Yuxi 仍仅是文档生命周期和资料展示的设计参考。本轮没有部署它的后端，没有引入它的 Agent 框架、向量数据库或数据库迁移。
