## 失败、发现及修复

- 首轮旧 UI 测试有 17 项失败：测试桩忽略 HTML 初始 disabled 状态。修复桩后旧 18 项通过，再扩充到当前 28 项。不能把测试桩失败当作真实服务故障。
- 首轮新 HTTP 测试 17 项因环境禁止监听本机端口而失败（EPERM）；获准本机监听后重跑，17 项通过。该次未发现应用断言失败。
- 复核修复：无效 UTF-8 在解析阶段显示明确失败；数据目录锁避免并发覆盖；拒绝变更较新数据库版本；前端处理按钮遵守后端状态；首次设置后更新顶部提示，迟到响应不得恢复过期提示。
- 编辑工具两次因同一路径删除和新增组合拒绝请求；没有局部写入，调整编辑方式后成功。保留操作失败记录。
- 浏览器上传文件选择工具发生长时间等待，返回后未确认文件选择及上传成功。本项验收未完成，不能视为通过，也没有据此认定产品上传功能失败。

最终自动化测试没有尚未修复的失败。

2. 如仅查看旧版，可在新目录运行 `git clone` 后执行 `git switch --detach dc9d23d50ba3c548f0b09b6f3c9f3d7a65e98f50`。这恢复的是 0.1 适配器，旧版需要 Yuxi 且不会读取新版本地数据库，不要误认为它能继续管理本地资料。
